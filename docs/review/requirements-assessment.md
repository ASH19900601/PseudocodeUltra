# 初版需求达成情况与竞争力评估

评估日期：2026-10-24（北京时间）。依据用户提供的《Pasted text.txt》初版方案、当前仓库源码、本机实际运行和本次检查记录。附件是待验收的需求材料；其中对考试规则、竞品弱点和实施建议的陈述不直接视为已验证事实。

**结论：项目已经具备可用的 M1–M4 本地学习 IDE 主流程，但尚未达到初版完整产品要求，现有证据也不足以认定整体优于 Pseudocode Pro。** 初版明确包含的考试、内容、教师和桌面功能尚有大块缺失。仓库将这些列为 M5，并从既有验收中排除，这能解释阶段交付范围，却不能据此判定用户的完整初版已经全部完成。本轮修复提升了已有功能的正确性和体验，没有把未实施模块改写成“已完成”。

## 本次证据的边界

本次尝试获取登记的 8 份官方 PDF 时，GET/HEAD 遇到 404 或超时，**没有完成当前官方原文下载及 SHA-256 复核**。仓库旧验收报告、固定散列清单和来源链接仍可作为历史记录，但不能当作这次已经重新验证“最新规范”或“每条来源准确”的证明。因此，本次可以确认实现与项目既定语义的行为，不能把规范认证或考试采分保证作为交付结论。应在拿到可信原文后，优先复核 ROUND、0478 下划线/文件模式、AS/A2 边界和近年 Insert 差异。

统一验收最后一次本机性能记录为：1,000 万次标量循环高速执行约 **75.74 ms**；10 万行文档完成冷分析后，一次非结构性编辑的核心诊断约 **13.49 ms**；冷分析约 **5,160.03 ms**。核心场景达到 1 秒/100 ms 阈值，但另做真实 Edge 的 10 万行一次性粘贴时长时间未完成并主动终止，**真实长文档界面体验仍未达标**。编辑器还有 400–450 ms 防抖，核心增量函数耗时不能冒充用户端诊断总延迟。原始记录见 [performance.json](validation/performance.json) 和 [ui-performance.json](ui-performance.json)。

本轮实际使用也发现了多项旧验收遗漏：空文档恢复、保存失败、运行状态与旧结果、文件备份、转换下载失效、语义漏检和追踪表筛选等。修复清单分别见 [语言与教学](language-fixes.md)、[运行器](runtime-fixes.md)、[界面与存储](web-fixes.md)。能够修复这些问题说明主流程得到改进；不能据此声称已消除所有用户体验问题。

## 与竞品的实际位置

2026-10-24 访问的 [Pseudocode Pro 官网](https://www.pseudocode.pro/) 仍公开列出 500 道挑战、真题起始代码、教师作业、桌面/移动应用、同步和三语言转换。这些是官网当前功能声明；本次没有登录购买或验证其收费教学流程。

其 [0478 编辑器功能页](https://www.pseudocode.pro/0478) 仍列出输入即运行、失焦运行、手动运行三种方式，以及追踪、导出和可视化。本项目本轮也补充了三种运行方式。主任务实际打开了竞品访客编辑器，页面正常载入，完成了 [8 个受控输入对照](competitor-comparison.md)；小样例不能替代跨版本、复杂类型和付费功能的全面评测。

初版附件对竞品“复杂类型追踪有 bug”“不严格”等说法不能照抄为当前结论。官网宣传不是独立验收，历史描述也不是当前缺陷证据；必须逐例控制方言、设置、运行完成状态和期望依据后，才能判断具体差异。出现输出不同时，也不能自动把本项目结果当作正确答案。

**竞争力判断：对中文学生的本机算法练习和课堂演示，本项目已有值得使用的能力；作为覆盖备考、作业和教师管理的完整产品，当前仍不足以替代竞品。** 可验证的产品特点是中文诊断、显式语义策略、保留源码结构的格式化、可暂停调试、追踪填空，以及带原生测试的三语言转换。这些支持“具备差异化基础”的判断，但“更严格符合考试”“复杂类型优于竞品”“全面超越”等结论仍缺相应官方复核和足量对照证据。

后续最直接的交付顺序是：取得可核验的官方原文并补规则覆盖；完成真正关闭辅助功能的考试模式与倒计时；加入有明确范围的原创题目和整题判分闭环；再按教师需求接入账号、班级和作业。完整英文界面、可恢复备份和长文档冷分析体验也应纳入验收。先把这些缺口变成可实测交付物，比继续增加功能名称更能提高竞争力。
